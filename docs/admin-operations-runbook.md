# 管理员日常运维手册

生成日期：2026-07-04

适用对象：平台管理员、运营、财务、值班运维。

目标：规范后台日常巡检、支付通道维护、订单处理、结算处理和高风险操作。

## 1. 每日巡检

建议每天固定时间检查一次，交易高峰期增加频率。

### 1.1 后台首页

路径：

```text
管理后台 -> 平台首页
```

检查项：

- 今日订单成功率是否低于近期基线。
- 今日订单数量是否异常。
- 支付方式收入是否有异常归零。
- 支付通道收入是否有异常归零。
- 商户余额和结算总额是否异常突增。
- 当前时间是否正常。

处理建议：

- 某通道收入为 0：检查通道状态、订单列表、插件配置、上游状态。
- 成功率明显下降：按通道、商户、金额段排查失败来源。
- 统计不显示历史日期：检查 `admin/ajax.php?act=getcount` 返回和浏览器控制台。

### 1.2 订单列表

路径：

```text
管理后台 -> 订单管理
```

检查项：

- 大量未支付订单。
- 大量已支付但通知失败订单。
- 冻结订单。
- 异常小额或重复金额订单。
- 某商户短时间大量失败订单。

处理建议：

- 已支付但商户未收到：先查 `notify_url`，确认商户幂等后补发通知。
- 大量未支付：检查对应通道是否可用，是否存在金额限制或跳转异常。
- 异常商户：必要时先关闭商户支付权限。

### 1.3 投诉列表

路径：

```text
管理后台 -> 其他功能 -> 交易投诉
```

检查项：

- 未处理投诉数量。
- 今日投诉数量。
- 昨日投诉数量。
- 高投诉商户。
- 高投诉通道。

处理建议：

- 优先处理未处理和即将超时投诉。
- 对高投诉商户降级通道、限制支付或要求整改。
- 对高投诉通道排查上游和商户业务类型。

### 1.4 结算列表

路径：

```text
管理后台 -> 结算管理
```

检查项：

- 长期待结算。
- 长期正在结算。
- 结算失败。
- 大额结算。
- 异常收款账号。

处理建议：

- 结算失败要填写清楚失败原因。
- 手动转账完成后再改为已完成。
- 对异常大额结算先核对订单和资金明细。

### 1.5 计划任务

路径：

```text
管理后台 -> 系统设置 -> 计划任务配置
```

检查项：

- crontab 是否存在。
- 是否使用 `https://`。
- curl 是否需要 `-L`。
- 最近订单通知是否正常推进。

处理建议：

- 如果大量订单 `notify` 未推进，优先检查计划任务。
- 修改计划任务后，手动运行一次确认返回正常。

## 2. 新商户开通流程

1. 创建或审核商户。
2. 确认商户资料完整。
3. 设置商户用户组。
4. 确认用户组绑定可用支付通道。
5. 配置授权域名。
6. 指导商户获取 API 信息。
7. 指导商户完成测试支付。
8. 检查异步通知成功。
9. 确认商户端幂等。
10. 允许正式上线。

后台路径：

```text
管理后台 -> 商户管理 -> 用户列表
管理后台 -> 商户管理 -> 用户组设置
管理后台 -> 商户管理 -> 授权域名
管理后台 -> 支付接口 -> 支付通道
```

开通注意事项：

- 新商户不要默认给全部通道权限。
- 高风险业务单独用户组。
- 未完成实名认证或资料不完整的商户，不建议开放正式收款。

## 3. 新支付通道上线流程

1. 上传或确认插件文件完整。
2. 进入支付插件页面刷新插件列表。
3. 确认支付方式存在并开启。
4. 新增支付通道。
5. 填写通道名称、插件、费率、成本、限额。
6. 填写插件配置。
7. 将通道分配给测试用户组。
8. 使用测试商户拉单。
9. 完成支付，确认订单已支付。
10. 确认异步通知成功。
11. 按低权重加入轮询。
12. 观察成功率和投诉率。
13. 稳定后逐步放量。

后台路径：

```text
管理后台 -> 支付接口 -> 支付插件
管理后台 -> 支付接口 -> 支付方式
管理后台 -> 支付接口 -> 支付通道
管理后台 -> 支付接口 -> 支付通道轮询
管理后台 -> 商户管理 -> 用户组设置
```

上线禁止项：

- 未测试直接分配给全部商户。
- 未确认回调直接放量。
- 未设置限额直接接大额订单。
- 未确认通道成本就启用利润统计。

## 4. 订单处理规范

### 4.1 查询订单

路径：

```text
管理后台 -> 订单管理
```

优先使用：

- 系统订单号。
- 商户订单号。
- 商户 ID。
- 支付账号。
- 网站域名。
- 支付 IP。

### 4.2 补发通知

补发前必须确认：

- 订单状态为已支付。
- 商户反馈未收到通知或商户系统状态未更新。
- 商户端已做幂等。
- 商户 `notify_url` 当前可访问。

不建议补发：

- 商户端无法确认幂等。
- 商户接口仍在报错。
- 商户接口发生 301/302 跳转且未处理。
- 订单本身状态异常。

### 4.3 人工改为已支付

这是高风险操作。

执行前必须确认：

- 上游确实已收款。
- 金额一致。
- 订单号一致。
- 商户一致。
- 支付方式和通道一致。
- 操作原因已记录。

执行后必须检查：

- 商户余额变化。
- 资金明细。
- 异步通知状态。
- 是否触发结算。

### 4.4 退款

退款前必须确认：

- 订单已支付。
- 退款金额正确。
- 上游支持退款。
- 商户余额足够扣除。
- 商户业务系统已确认退款请求。

退款后必须确认：

- 平台订单状态。
- 上游退款状态。
- 商户资金明细。
- 投诉状态，如有投诉。

## 5. 结算处理规范

### 5.1 生成批次

路径：

```text
管理后台 -> 结算管理 -> 批量结算
```

生成前：

- 确认待结算金额。
- 排除异常商户。
- 排除投诉中或风险中的订单。
- 导出或记录当前待结算列表。

生成后：

- 待结算记录会变为正在结算。
- 自动转账成功后状态变为已完成。
- 手动转账需人工改为已完成。

### 5.2 结算失败处理

常见原因：

- 收款账号错误。
- 姓名不一致。
- 上游转账失败。
- 商户余额不足。
- 结算通道异常。

处理步骤：

1. 填写失败原因。
2. 通知商户修改收款资料。
3. 修改后重新发起结算或人工处理。
4. 保留操作记录。

## 6. 投诉处理规范

投诉处理路径：

```text
管理后台 -> 其他功能 -> 交易投诉
```

处理步骤：

1. 获取最新投诉数据。
2. 打开投诉详情。
3. 核对关联订单。
4. 核对商户、通道、金额、支付账号。
5. 联系商户处理。
6. 根据实际情况回复、上传凭证、退款或结案。
7. 记录处理结论。

风控动作：

- 投诉高发商户：关闭支付或降级通道。
- 投诉高发商品：要求商户整改。
- 投诉高发通道：降低权重或暂停。
- 恶意投诉买家：加入黑名单。

## 7. 支付成功率排查流程

当成功率明显下降时，按顺序排查：

1. 后台首页查看整体成功率。
2. 按支付方式看收入和订单。
3. 按支付通道看收入和订单。
4. 订单列表筛选未支付和异常订单。
5. 查看是否集中在某商户。
6. 查看是否集中在某金额。
7. 查看是否集中在某设备或浏览器。
8. 检查通道是否被上游限制。
9. 检查通道限额和单笔最小最大金额。
10. 检查插件日志和 PHP 错误日志。

处理动作：

- 单通道异常：关闭通道或降低轮询权重。
- 单商户异常：关闭商户支付或调整用户组。
- 单金额异常：调整单笔限额或风控规则。
- 上游异常：切换备用通道。

## 8. 高风险操作审批建议

以下操作建议至少双人确认：

- 人工改订单为已支付。
- 大额退款。
- 批量结算。
- 删除商户。
- 修改商户余额。
- 修改通道模式。
- 替换支付插件。
- 重置商户密钥。
- 修改回调专用网址。
- 修改计划任务密钥。

记录内容：

- 操作人。
- 操作时间。
- 操作对象。
- 操作原因。
- 操作前状态。
- 操作后状态。
- 关联订单号或商户号。

## 9. 交接班清单

值班交接时至少说明：

- 当前总订单量和成功率。
- 异常通道。
- 异常商户。
- 未处理投诉。
- 正在处理的结算批次。
- 今日已执行的高风险操作。
- 需要继续观察的问题。

## 10. 每周维护清单

- 检查服务器磁盘、内存、PHP、Nginx。
- 检查 PHP fatal error。
- 检查支付插件目录是否有异常文件。
- 检查计划任务。
- 检查高投诉商户。
- 检查失败通知。
- 检查结算失败记录。
- 检查黑名单和风控记录。
- 检查备份可用性。
- 检查 README 和使用文档是否需要更新。
