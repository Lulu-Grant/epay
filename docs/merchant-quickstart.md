# 商户快速上手指南

生成日期：2026-07-04

适用对象：新接入商户、商户技术人员、平台客服。

目标：让商户在最短时间内完成登录、资料配置、接口对接、测试支付和上线验收。

## 1. 登录用户中心

访问：

```text
https://epay.tianlupay.com/user/login.php
```

登录方式以平台配置为准：

- 手机号/邮箱 + 密码。
- 商户密钥登录。

首次登录后，如果系统要求补全资料，先完成资料补全，否则可能无法收款、提现或查看完整功能。

## 2. 完善结算资料

路径：

```text
用户中心 -> 个人资料 -> 修改资料
```

必须确认：

- 结算方式正确。
- 收款账号正确。
- 真实姓名与收款账号主体一致。
- 手机号或邮箱可正常接收验证码。

如果平台开启强制实名认证，必须先完成：

```text
用户中心 -> 个人资料 -> 实名认证
```

## 3. 获取 API 信息

路径：

```text
用户中心 -> 个人资料 -> API 信息
```

对接前记录：

- 商户 ID：接口参数 `pid`。
- 平台公钥：用于验证平台返回数据和异步通知。
- 商户私钥：用于商户请求签名。

密钥安全要求：

- 商户私钥只能放在服务端。
- 不要放入前端页面、App、浏览器缓存或公开仓库。
- 密钥泄露后立即联系平台重置，并同步更新业务系统。

## 4. 阅读开发文档

V2 文档：

```text
https://epay.tianlupay.com/doc.html
```

旧版 V1 文档：

```text
https://epay.tianlupay.com/doc_old.html
```

新接入优先使用 V2 接口。V2 接口使用 RSA 签名，签名算法为 `SHA256WithRSA`。

## 5. 推荐对接顺序

1. 商户系统生成本地订单。
2. 调用平台页面跳转支付或统一下单接口。
3. 用户完成支付。
4. 平台异步请求商户 `notify_url`。
5. 商户验签通知数据。
6. 商户按 `out_trade_no` 幂等更新本地订单。
7. 商户返回平台要求的成功响应。
8. 用户从 `return_url` 返回商户页面。

关键原则：

- 最终入账依据是异步通知或主动查询结果，不是浏览器跳转。
- `out_trade_no` 必须唯一。
- 商户处理通知必须幂等。
- 同一个订单重复收到通知时，不能重复发货、重复加余额或重复开通服务。

## 6. 支付接口必填项

以 `/doc.html` 实际文档为准，常用字段包括：

| 字段 | 说明 |
| --- | --- |
| `pid` | 商户 ID |
| `type` | 支付方式，例如 `alipay` |
| `out_trade_no` | 商户订单号 |
| `notify_url` | 异步通知地址 |
| `return_url` | 页面跳转地址 |
| `name` | 商品名称 |
| `money` | 订单金额 |
| `timestamp` | 当前时间戳 |
| `sign` | 签名 |
| `sign_type` | 签名类型 |

注意：

- 金额最多两位小数。
- 商品名称不要过长。
- `notify_url` 必须公网可访问。
- `notify_url` 不应返回 301/302 跳转。

## 7. 测试支付

测试方式一：使用用户中心测试页。

```text
https://epay.tianlupay.com/user/test.php
```

测试方式二：由商户系统发起真实接口请求。

测试必须覆盖：

- 创建订单成功。
- 页面能跳到支付页或返回支付二维码。
- 支付成功后平台订单状态为已支付。
- 商户能收到异步通知。
- 商户能验签通知。
- 商户本地订单状态正确更新。
- 重复补发通知不会重复处理。

## 8. 查看订单

路径：

```text
用户中心 -> 订单记录
```

建议按以下字段排查：

- 系统订单号。
- 商户订单号。
- 商品名称。
- 订单金额。
- 支付状态。
- 支付方式。
- 创建时间和完成时间。

状态判断：

| 状态 | 含义 | 商户动作 |
| --- | --- | --- |
| 未支付 | 用户未完成支付 | 等待或引导用户重新支付 |
| 已支付 | 平台已确认收款 | 发货或开通服务 |
| 已退款 | 订单已退款 | 本地订单同步退款状态 |
| 已冻结 | 订单被风控或人工冻结 | 联系平台核查 |

## 9. 补单与通知

如果平台订单已支付，但商户系统没有变更：

1. 先检查商户 `notify_url` 日志。
2. 确认商户接口没有报错。
3. 确认商户接口没有跳转。
4. 确认商户接口返回了平台要求的成功响应。
5. 确认商户端具备幂等能力。
6. 再在订单记录中使用“补单”。

补单风险：

- 如果商户端没有幂等处理，补单可能导致重复发货或重复开通。
- 商户必须以订单号作为唯一处理依据。

## 10. 退款

如果平台开启商户退款权限，订单记录中会显示退款入口。

退款前确认：

- 订单状态为已支付。
- 退款金额正确。
- 商户余额或上游退款能力满足要求。
- 商户业务系统同步退款状态。

退款后应再次查询订单状态，并核对资金明细。

## 11. 提现与结算

查看结算记录：

```text
用户中心 -> 结算记录
```

申请提现：

```text
用户中心 -> 申请提现
```

提现前确认：

- 商户状态正常。
- 收款账号正确。
- 可提现余额满足最低提现金额。
- 当日提现次数未超限。

结算失败时，点击失败状态查看原因，并根据提示修改收款账号或联系平台处理。

## 12. 交易投诉

路径：

```text
用户中心 -> 交易投诉
```

收到投诉后：

1. 查看投诉详情。
2. 核对关联订单。
3. 联系用户沟通。
4. 根据实际情况退款、回复、上传凭证或提交处理结果。
5. 继续关注投诉状态。

注意：

- 投诉不要拖延处理。
- 不确认订单和用户诉求前不要直接结案。
- 已退款的投诉也需要确认投诉状态是否同步完成。

## 13. 上线前检查清单

商户正式上线前，逐项确认：

- 用户中心可正常登录。
- 结算资料已填写。
- API 信息已获取。
- 商户私钥已安全保存。
- 商户系统签名通过。
- 支付创建成功。
- 支付成功后平台订单变为已支付。
- 商户能收到异步通知。
- 商户能验签通知。
- 商户端重复通知幂等。
- 订单查询接口可用。
- 退款能力已按业务需要验证。
- 授权域名已配置。
- 正式商品名称和金额符合平台规则。

## 14. 联系平台时提供的信息

遇到问题时，尽量提供：

- 商户 ID。
- 系统订单号。
- 商户订单号。
- 支付方式。
- 支付金额。
- 下单时间。
- 商户 `notify_url`。
- 商户服务器返回状态码和日志。
- 截图或错误提示。

不要通过聊天工具发送商户私钥、管理员账号、服务器密码、数据库密码。
