# PHP 8.4 升级验收标准

生成日期：2026-06-22

目标：定义彩虹易支付升级到 PHP 8.4 且兼容 PHP 7.4 的可验收条件。只有本文档中的阻断项全部通过，才允许进入生产灰度。

## 验收结论分级

验收结果分为三类：

- 通过：所有阻断项通过，非阻断问题有明确记录和处理计划。
- 有条件通过：阻断项通过，但存在低风险非阻断问题，需要灰度期间重点监控。
- 不通过：任一阻断项失败，禁止进入生产灰度。

## 阻断项总览

以下任一项失败即视为不通过：

- PHP 7.4 语法检查失败。
- PHP 8.4 语法检查失败。
- 核心入口出现 fatal error。
- 安装或升级流程不可用。
- 后台无法登录。
- 用户中心无法登录。
- 支付创建失败。
- 支付回调无法正确更新订单。
- 已支付订单重复回调导致资金或状态异常。
- P0 支付插件不可加载。
- Composer 依赖无法重复安装。
- 生产回滚路径不可用。

## 环境验收

### PHP 7.4 环境

必须满足：

- PHP 版本为 7.4.x。
- 必需扩展已安装：pdo_mysql、curl、openssl、json、mbstring、gd、fileinfo、session。
- 建议扩展已安装或有替代方案：gmp、bcmath、intl、zip、xml。
- 项目可完成初始化加载。
- 旧版本核心业务回归通过。

验收命令示例：

```bash
php -v
php -m
```

### PHP 8.4 环境

必须满足：

- PHP 版本为 8.4.x。
- 必需扩展与 PHP 7.4 环境一致。
- OpenSSL 可用。
- PDO MySQL 可连接测试数据库。
- GD 可生成验证码图片。
- curl 可访问外部接口。

验收命令示例：

```bash
php -v
php -m
php -r "var_dump(extension_loaded('pdo_mysql'), extension_loaded('openssl'), extension_loaded('curl'));"
```

## 代码静态验收

### 语法检查

PHP 7.4 和 PHP 8.4 均必须通过：

```bash
find . -path './.git' -prune -o -name '*.php' -print0 | xargs -0 -n1 php -l
```

通过标准：

- 0 个 parse error。
- 0 个 fatal error。
- PHP 8.4 下不得出现业务代码语法不兼容。

### PHP 7.4 语法下限

必须满足：

- 不使用 union type。
- 不使用 match 表达式。
- 不使用 enum。
- 不使用 readonly。
- 不使用构造器属性提升。
- 不使用 PHP 8 专属 attribute。
- 不使用 typed class constant。
- 不使用只存在于 PHP 8.x 的标准库函数，除非有兼容 polyfill。

### 明确弃用项

必须满足：

- 业务代码中不再使用 `strftime()`。
- 业务代码中不出现 `each()`、`create_function()`、`__autoload()`、`mysql_*()`、`mcrypt_*()`。
- PHP 8.4 测试环境中不得出现来自业务代码的批量 deprecated。
- vendor deprecated 必须记录来源、影响范围和处理策略。

## Composer 与依赖验收

必须满足：

- `includes/composer.json` 声明 PHP 版本范围。
- 依赖版本可在 PHP 7.4 和 PHP 8.4 下解析。
- 提交 `composer.lock`，或明确文档说明不提交的原因和替代锁定机制。
- `composer install` 可重复执行成功。
- 不得依赖开发者本机已有 vendor 才能运行。

验收命令示例：

```bash
composer validate --working-dir=includes --strict
composer install --working-dir=includes --no-dev
composer check-platform-reqs --working-dir=includes
```

通过标准：

- validate 通过。
- install 通过。
- platform requirements 通过。
- 依赖版本与锁文件一致。

## 运行时错误验收

测试环境必须开启完整错误报告：

```php
error_reporting(E_ALL);
ini_set('display_errors', '0');
ini_set('log_errors', '1');
```

通过标准：

- 核心链路无 fatal error。
- 核心链路无 uncaught exception。
- 核心链路无 warning 级别高频日志。
- deprecated 日志全部登记，业务代码 deprecated 必须修复。
- vendor deprecated 如暂不修复，必须有风险接受记录。

## 核心入口验收

以下入口在 PHP 7.4 和 PHP 8.4 下均必须可访问或可执行：

| 入口 | 验收内容 |
| --- | --- |
| `/` | 首页可正常加载 |
| `/install/` | 未安装状态下安装页可正常加载 |
| `/install/update.php` | 升级页可正常加载 |
| `/admin/` | 后台登录页可正常加载 |
| `/user/` | 用户中心可正常加载 |
| `/submit.php` | 缺少参数时返回预期错误 |
| `/mapi.php` | 缺少参数时返回 JSON 错误 |
| `/api.php` | 缺少参数时返回 JSON 错误 |
| `/pay/submit/{trade_no}/` | 可进入支付提交流程 |
| `/cron.php` | 定时任务可执行 |

通过标准：

- HTTP 状态码符合预期。
- 页面不出现 PHP 错误输出。
- JSON 接口返回合法 JSON。
- 入口行为与 PHP 7.4 基线一致。

## 数据库验收

必须满足：

- 新安装流程可创建完整表结构。
- 从现有版本升级后 `DB_VERSION` 正确。
- `pre_config` 可读取。
- `pre_order` 可创建、更新、查询。
- `pre_user` 可登录、更新配置。
- `pre_channel` 可新增、禁用、启用。
- `pre_settle` 可创建、更新状态。
- `pre_transfer` 可查询和更新状态。

通过标准：

- PHP 7.4 与 PHP 8.4 对同一数据库样本执行核心流程结果一致。
- 无 SQL fatal error。
- 无订单状态异常。
- 无金额字段精度异常。

## 认证与权限验收

后台必须验证：

- 管理员登录成功。
- 管理员登录失败提示正确。
- 管理员退出登录成功。
- 后台未登录访问受保护页面会被拦截。
- `admin_token` cookie 行为正常。

用户中心必须验证：

- 用户登录成功。
- 用户登录失败提示正确。
- 用户退出登录成功。
- 用户未登录访问受保护页面会被拦截。
- `user_token` cookie 行为正常。

通过标准：

- PHP 7.4 和 PHP 8.4 行为一致。
- cookie 有效期符合预期。
- 受保护页面不泄露敏感信息。

## 支付核心验收

### 订单创建

必须验证：

- 页面支付提交创建订单。
- API 支付提交创建订单。
- 商户号不存在时返回预期错误。
- 签名错误时返回预期错误。
- 金额非法时返回预期错误。
- 重复商户订单号处理符合现有规则。

通过标准：

- 订单号生成正确。
- 订单金额正确。
- 商户 ID 正确。
- 支付方式正确。
- 初始订单状态正确。

### 支付跳转

必须验证：

- `jump` 类型返回可跳转 URL。
- `html` 类型返回表单。
- `qrcode` 类型返回二维码页面。
- `scheme` 类型返回 URL scheme 页面。
- `json` 类型返回合法 JSON。
- 错误时返回统一错误页或 JSON。

通过标准：

- 返回结构与 PHP 7.4 基线一致。
- 不出现空白页。
- 不出现 PHP warning 输出。

### 异步通知

必须验证：

- 正确签名通知可更新订单状态。
- 错误签名通知被拒绝。
- 重复通知不会重复入账。
- 已完成订单重复通知行为符合现有规则。
- 通知商户失败时会记录并重试。

通过标准：

- 订单状态从未支付变为已支付。
- `api_trade_no` 正确保存。
- `buyer` 信息按规则保存。
- 商户通知记录正确。
- 重复回调无资金重复变动。

### 同步返回

必须验证：

- 支付成功后同步跳转到商户 return_url。
- 超过限制时间后按现有规则跳转。
- 失败订单跳转失败页。

通过标准：

- 跳转地址正确。
- 签名参数正确。
- 行为与 PHP 7.4 基线一致。

## 支付插件验收

### 插件分级

P0 插件必须完整验收：

- `alipay`
- `wxpay`
- `qqpay`
- `epay`
- `epayn`

P1 插件必须完成配置读取、加载和至少一条核心支付路径验证：

- `stripe`
- `paypal`
- `unionpay`
- `swiftpass`
- `swiftpass2`
- `kuaiqian`
- `ysepay`
- `sandpay`

P2 插件必须完成批量加载验收：

- 其他插件。

### 插件加载

每个插件必须验证：

- 插件主文件存在。
- 插件类存在。
- `$info` 元信息可读取。
- 支付类型声明正确。
- 配置项结构可读取。
- 不因 PHP 8.4 产生 fatal error。

通过标准：

- P0/P1 插件 100% 通过。
- P2 插件如失败，必须记录为不兼容插件，并在后台禁用或标记。

### 插件支付路径

P0/P1 插件必须验证：

- `submit` 方法。
- `mapi` 方法，如插件支持。
- `notify` 方法。
- `return` 方法。
- `refund` 方法，如插件支持。

通过标准：

- 返回结构符合 `Payment::echoDefault` 或 `Payment::echoJson` 预期。
- 验签成功和失败分支均正确。
- 证书文件缺失时错误提示可控。
- PHP 7.4 与 PHP 8.4 结果一致。

## OpenSSL 与签名验收

必须验证：

- MD5 签名生成一致。
- RSA 签名生成可验签。
- RSA 公钥验签成功。
- 错误公钥验签失败。
- PEM/base64 key 转换正确。
- 证书文件读取失败时错误可控。

通过标准：

- PHP 7.4 与 PHP 8.4 对同一输入的验签结果一致。
- 关键支付插件不出现签名格式变化。
- OpenSSL 错误不会直接输出到页面。

## 退款、结算、转账验收

退款必须验证：

- 退款查询。
- 退款提交。
- 不支持退款的插件返回明确错误。
- 重复退款处理符合现有规则。

结算必须验证：

- 结算列表。
- 创建结算批次。
- 完成结算批次。
- 修改结算状态。

转账必须验证：

- 转账列表。
- 转账结果查询。
- 转账凭证查询。
- 转账状态更新。

通过标准：

- 金额不丢精度。
- 状态转换正确。
- PHP 7.4 与 PHP 8.4 结果一致。

## 安装与升级验收

新安装必须验证：

- `/install/` 可正常打开。
- 数据库连接失败提示正确。
- 数据表创建成功。
- 默认管理员可登录。
- 安装完成后生成或要求 `install.lock`。

老库升级必须验证：

- 低于当前 `DB_VERSION` 的数据库可进入升级流程。
- 升级 SQL 可重复执行或重复执行有明确保护。
- 升级后配置可读取。
- 升级后订单、用户、通道数据保留。

通过标准：

- 新安装成功。
- 老库升级成功。
- 升级失败可回滚。

## 安全回归验收

必须验证：

- 未安装时安全提示正常。
- 缺失 `install.lock` 时阻止运行。
- 后台敏感操作需要登录。
- 用户只能访问自己的订单、结算、转账数据。
- 支付回调验签失败不更新订单。
- 下载接口不允许越权读取非预期文件。

通过标准：

- 无明显越权。
- 无未登录访问敏感接口。
- 支付回调签名失败路径安全。

## 性能与稳定性验收

必须记录：

- 首页响应时间。
- 后台首页响应时间。
- 用户中心首页响应时间。
- 创建订单接口响应时间。
- 支付回调处理时间。
- `cron.php` 执行时间。

通过标准：

- PHP 8.4 响应时间不低于 PHP 7.4 基线 20% 以上。
- 支付回调无明显变慢。
- 无 PHP-FPM worker 异常退出。
- 错误日志无高频新增错误。

## 灰度验收

灰度前必须满足：

- 所有阻断项通过。
- 回滚方案已演练。
- 数据库已备份。
- 日志和监控已启用。
- P0 插件已完整通过。

灰度期间必须监控：

- 支付成功率。
- 支付回调成功率。
- 商户通知成功率。
- 退款失败率。
- PHP fatal error 数量。
- PHP warning/deprecated 数量。
- 慢查询数量。
- 订单状态不一致数量。

灰度通过标准：

- 至少连续 24 小时无阻断错误。
- 支付成功率不低于 PHP 7.4 基线。
- 异步通知成功率不低于 PHP 7.4 基线。
- 无订单资金状态异常。
- 无批量签名或验签失败。

## 回滚验收

必须满足：

- 可在 30 分钟内切回 PHP 7.4。
- 旧版本代码或旧运行环境可恢复。
- 数据库备份可恢复。
- 回滚后后台、用户中心、支付创建、支付回调可用。

触发回滚条件：

- 支付成功率显著下降。
- 异步通知失败率显著上升。
- 出现批量签名失败。
- 出现订单重复入账或状态错乱。
- 出现持续 fatal error。
- 出现无法快速修复的插件兼容问题。
