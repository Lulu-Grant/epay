# 彩虹易支付用户使用文档

生成日期：2026-07-04

适用版本：Version 3075 及当前定制版本

本文档面向三类人员：

- 商户用户：使用用户中心查看订单、配置接口、处理结算和投诉。
- 平台管理员：使用管理后台维护商户、订单、支付通道、结算和系统配置。
- 对接开发人员：按平台接口文档完成支付、通知、查询、退款、代付等对接。

本文档只说明系统使用流程和操作注意事项，不包含服务器账号、数据库账号、支付通道密钥等敏感信息。

## 角色与权限

### 商户用户

商户用户主要操作范围：

- 查看商户余额、订单总数、今日订单、昨日订单、今日收入、昨日收入。
- 查看 API 信息，生成或查看接口密钥。
- 修改结算账号、联系方式、通知开关和扣费模式。
- 查询订单记录、资金明细、结算记录。
- 申请提现、余额充值、购买会员或用户组。
- 处理交易投诉。
- 查看开发文档并完成接口对接。

### 平台管理员

平台管理员主要操作范围：

- 查看平台首页统计、收入统计、订单成功率。
- 管理商户、用户组、商户费率、资金明细和授权域名。
- 管理订单、退款、补单、通知重发、黑名单、风控记录。
- 管理支付插件、支付方式、支付通道、通道轮询、公众号/小程序配置。
- 管理结算记录、批量结算、企业付款、分账规则。
- 配置网站信息、支付参数、结算规则、消息提醒、计划任务、验证码、注册开关。
- 处理交易投诉。

### 对接开发人员

开发人员主要使用：

- 用户中心 -> 个人资料 -> API 信息。
- `/doc.html` 开发文档。
- `/doc_old.html` 旧版接口文档。
- 测试支付页或接口请求工具。

开发人员不应使用管理员账号进行日常对接测试。

## 商户使用流程

### 1. 登录用户中心

访问：

```text
https://epay.tianlupay.com/user/login.php
```

可用登录方式以站点配置为准：

- 手机号/邮箱 + 密码登录。
- 密钥登录。

如果登录后提示补全资料，先按页面要求完成结算账号、真实姓名、联系方式等基础资料。

### 2. 完善资料

路径：

```text
用户中心 -> 个人资料 -> 修改资料
```

重点字段：

- 结算方式：支付宝、微信、QQ 钱包、银行卡，具体选项以平台开启项为准。
- 收款账号：对应结算方式的账号、OpenId 或银行卡号。
- 真实姓名：必须与结算账号主体一致。
- 手机号/邮箱：用于登录验证、通知和找回密码。
- 订单退款 API 接口：开启后允许商户通过接口发起退款。
- 代付 API 接口：开启后允许商户通过接口发起代付。
- 结算通知：开启后可接收结算结果通知。
- 交易投诉通知：开启后可接收投诉提醒。
- 扣费模式：余额扣费或订单加费。

注意事项：

- 结算账号变更会影响后续提现或自动结算。
- 绑定手机号、邮箱通常需要验证码。
- 涉及资金的配置变更建议由商户负责人操作，并保留变更记录。

### 3. 查看 API 信息

路径：

```text
用户中心 -> 个人资料 -> API 信息
```

主要信息：

- 商户 ID：接口参数 `pid`。
- 商户密钥或 RSA 密钥：用于签名。
- 平台公钥：用于验签平台返回和异步通知。
- 商户私钥：用于接口请求签名，应由商户自行妥善保存。

V2 接口使用 `SHA256WithRSA` 签名。具体签名规则以 `/doc.html` 中“签名规则”为准。

安全要求：

- 商户私钥不得放到前端页面、App 包体或公开仓库。
- 密钥泄露后应立即重置，并同步更新商户业务系统。
- 生产环境和测试环境建议使用不同商户号或不同密钥。

### 4. 对接支付

推荐流程：

1. 阅读 `https://epay.tianlupay.com/doc.html`。
2. 在 API 信息页面生成或确认 RSA 密钥。
3. 先对接页面跳转支付或统一下单接口。
4. 配置 `notify_url` 和 `return_url`。
5. 完成异步通知验签和订单状态更新。
6. 使用小额订单测试支付创建、支付完成、异步通知、订单查询。
7. 测试成功后再切换到生产商品和真实金额。

常用接口：

| 场景 | 文档位置 |
| --- | --- |
| 页面跳转支付 | `/doc.html` -> 支付相关接口 -> 页面跳转支付 |
| 统一下单 | `/doc.html` -> 支付相关接口 -> 统一下单接口 |
| 订单查询 | `/doc.html` -> 支付相关接口 -> 订单查询 |
| 订单退款 | `/doc.html` -> 支付相关接口 -> 订单退款 |
| 支付结果通知 | `/doc.html` -> 支付相关接口 -> 支付结果通知 |
| 商户信息查询 | `/doc.html` -> 商户相关接口 -> 查询商户信息 |
| 代付 | `/doc.html` -> 代付相关接口 |

对接注意事项：

- `out_trade_no` 必须由商户系统保证唯一。
- `notify_url` 必须公网可访问，且不能依赖浏览器跳转。
- 商户系统处理异步通知必须做幂等：同一个订单重复收到通知时不能重复发货或重复加款。
- 平台通知返回成功标识后，平台才会认为通知完成。
- `return_url` 只用于用户浏览器跳转展示，不能作为最终入账依据。
- 金额最多保留两位小数。
- 如果平台开启授权域名，发起支付的业务域名必须在授权域名列表中。

### 5. 查看订单

路径：

```text
用户中心 -> 订单记录
```

支持按以下条件查询：

- 系统订单号。
- 商户订单号。
- 商品名称。
- 商品金额。
- 实付金额。
- 网站域名。
- 支付 IP。
- 支付账号。
- 日期范围。
- 支付方式。
- 支付状态。

订单状态说明：

| 状态 | 说明 |
| --- | --- |
| 未支付 | 已创建订单，但用户未完成支付 |
| 已支付 | 支付成功，平台已完成订单入账 |
| 已退款 | 订单已退款 |
| 已冻结 | 订单被风控或人工冻结 |
| 预授权 | 授权类支付流程中的中间状态 |

常用操作：

- 查看详情：点击系统订单号。
- 明细：查看该订单相关资金流水。
- 补单：重新触发商户异步通知。补单前确认商户系统具备幂等处理能力。
- 退款：如平台开启商户退款权限，可由商户发起退款。

### 6. 查看资金明细

路径：

```text
用户中心 -> 资金明细
```

用于核对余额变化。常见流水类型包括：

- 订单收入。
- 手续费扣除。
- 手动提现。
- 余额充值。
- 退款扣款。
- 会员购买。
- 实名认证扣费。

出现余额不一致时，先按订单号查询资金明细，再核对订单状态和结算状态。

### 7. 查看结算记录

路径：

```text
用户中心 -> 结算记录
```

结算状态：

| 状态 | 说明 |
| --- | --- |
| 待结算 | 已生成结算记录，尚未处理 |
| 正在结算 | 已进入批量结算或转账处理中 |
| 已完成 | 结算成功 |
| 结算失败 | 结算失败，可点击查看失败原因 |

结算金额以平台结算规则为准，可能扣除结算手续费。

### 8. 申请提现

路径：

```text
用户中心 -> 申请提现
```

该入口只有在平台开启手动提现时显示。

提现前检查：

- 商户状态正常。
- 结算账号已填写且无误。
- 当前余额或可提现余额满足最低提现金额。
- 当日手动提现次数未超限。

提现模式：

- D+0：可提现余额通常为截止当前的可用收入。
- D+1：可提现余额通常为截止前一天的可用收入。

实际到账时间以平台结算配置和上游转账状态为准。

### 9. 余额充值

路径：

```text
用户中心 -> 余额充值
```

余额常用于：

- 支付通道为“商户直清”时扣除手续费。
- 订单退款。
- 实名认证费用。
- 购买会员或用户组。

注意事项：

- 充值余额不应作为频繁大额充值后提现的通道。
- 充值失败但已扣款时，保留订单号并联系平台管理员核查。

### 10. 授权域名

路径：

```text
用户中心 -> 授权域名
```

该入口只有在平台开启授权域名功能时显示。

用途：

- 限制商户只能从已授权业务域名发起支付。
- 降低盗用商户号和非法拉单风险。

填写要求：

- 填写业务站点域名，不包含路径。
- 通配符支持情况以平台后台说明为准。
- 域名变更后应及时更新，否则可能出现支付创建失败。

### 11. 交易投诉处理

路径：

```text
用户中心 -> 交易投诉
```

该入口只有在平台开启交易投诉功能时显示。

处理流程：

1. 查看投诉列表，重点关注未处理投诉。
2. 点击投诉详情，查看关联订单、问题类型、投诉原因、投诉详情、联系方式、第三方投诉单号。
3. 与用户充分沟通。
4. 根据实际情况选择处理结果、回复留言、上传凭证或退款。
5. 提交处理结果后继续关注投诉状态。

注意事项：

- 不要在未沟通或未核实订单的情况下直接结案。
- 涉及退款时，先确认订单、金额、收款账号和退款能力。
- 投诉处理记录会影响商户风控判断。

## 管理员使用流程

### 1. 登录管理后台

访问：

```text
https://epay.tianlupay.com/admin/login.php
```

登录后进入平台首页。

安全要求：

- 管理员密码必须修改默认值。
- 管理后台账号只给必要人员使用。
- 避免在公共网络或非可信设备登录后台。
- 出现异常登录日志时，立即修改密码并检查服务器访问日志。

### 2. 平台首页统计

路径：

```text
管理后台 -> 平台首页
```

主要指标：

- 订单数量。
- 商户数量。
- 商户余额。
- 结算总额。
- 今日订单成功率。
- 当前时间。
- 支付方式收入统计。
- 支付通道收入统计。
- 支付方式手续费利润。

当前定制版本的首页收入统计直接从订单表聚合最近 7 天成功订单数据；即使历史缓存缺失，也应显示历史日期记录。

使用建议：

- 每日先看今日订单成功率和通道收入分布。
- 如果某个通道今日收入为 0，应结合订单列表和通道状态排查。
- 手续费利润为统计口径数据，实际财务以资金明细和上游账单为准。

### 3. 商户管理

路径：

```text
管理后台 -> 商户管理 -> 用户列表
```

常用操作：

- 搜索商户：按商户号、密钥、结算账号、域名、QQ、手机号、邮箱等查询。
- 添加商户：为内部或指定客户创建商户号。
- 编辑商户：修改基础信息、状态、用户组、结算信息。
- 登录商户：以管理员身份进入商户用户中心排查问题。
- 查看订单、结算、明细。
- 重置密钥。
- 封禁或关闭支付、结算权限。

状态含义：

| 状态 | 说明 |
| --- | --- |
| 用户状态正常 | 商户账号可用 |
| 用户状态封禁 | 商户无法正常使用 |
| 支付状态正常 | 可以发起支付 |
| 支付状态关闭 | 禁止发起支付 |
| 结算状态正常 | 可以结算 |
| 结算状态关闭 | 禁止结算 |
| 待审核用户 | 注册后等待管理员审核 |

操作风险：

- 删除商户前必须确认没有未完成订单、未结算余额和投诉。
- 重置密钥会导致商户现有接口签名失败，必须通知商户同步更新。
- 关闭支付不会自动处理已创建订单，需要结合订单状态判断。

### 4. 用户组与费率

路径：

```text
管理后台 -> 商户管理 -> 用户组设置
```

用途：

- 给不同商户配置不同通道、分成比例、结算手续费、代付手续费、邀请返现比例。
- 控制商户能使用哪些支付通道。

原则：

- 默认用户组适合普通商户。
- 高风险或测试商户应单独分组。
- 新增通道后，检查目标用户组是否已配置该通道。
- 修改费率前先确认费率含义：通道成本、平台分成、商户到账之间不要混淆。

用户组购买：

```text
管理后台 -> 商户管理 -> 用户组购买
```

用于允许商户自行购买或续期指定用户组。

### 5. 订单管理

路径：

```text
管理后台 -> 订单管理
```

支持按系统订单号、商户订单号、接口订单号、商品名称、金额、网站域名、支付账号、支付 IP 等查询。

常用操作：

- 查看订单详情。
- 查看关联商户。
- 查看支付通道。
- 退款。
- 补发通知。
- 加入黑名单。
- 人工改为已支付。
- 冻结或解冻订单。
- 导出订单。

高风险操作：

- 人工改为已支付：会给商户分成，必须确认实际收款。
- 退款：确认上游退款能力和商户余额扣款规则。
- 补发通知：确认商户端幂等，避免重复发货。
- 删除或变更状态：先保留订单号和操作原因。

### 6. 结算管理

路径：

```text
管理后台 -> 结算管理
```

结算列表用于查看和处理每个商户的结算记录。

批量结算：

```text
管理后台 -> 结算管理 -> 批量结算
```

操作流程：

1. 确认待结算记录。
2. 点击生成结算批次。
3. 导出结算表格或通过转账接口批量转账。
4. 自动转账成功后状态变为已完成。
5. 手动转账场景下，转账完成后手动改为已完成。
6. 转账失败时填写失败原因，便于商户查看。

注意事项：

- 生成结算批次会将待结算记录改为正在结算。
- 手动改为已完成前必须确认实际资金已转出。
- 删除结算记录可能退回商户余额，操作前必须核对。

### 7. 支付插件、支付方式、支付通道

#### 支付插件

路径：

```text
管理后台 -> 支付接口 -> 支付插件
```

用途：

- 查看系统已识别的支付插件。
- 新插件放入 `/plugins/` 后点击刷新插件列表。

注意事项：

- 插件目录结构必须符合系统要求。
- 插件缺少配置文件或入口文件会导致下单 fatal error。
- 新插件上线前必须先在测试通道验证。

#### 支付方式

路径：

```text
管理后台 -> 支付接口 -> 支付方式
```

字段说明：

- 调用值：接口传入的 `type`，例如 `alipay`。
- 显示名称：前台和后台展示名称。
- 支持设备：PC、Mobile 或 PC+Mobile。
- 状态：开启后商户才可选择。

注意事项：

- 调用值必须与开发文档和插件支持的支付方式一致。
- 同一个调用值和支持设备不能重复。

#### 支付通道

路径：

```text
管理后台 -> 支付接口 -> 支付通道
```

字段说明：

- 显示名称：后台识别用。
- 分成比例：给商户的分成比例。
- 通道成本：用于统计利润，可留空。
- 通道模式：平台代收或商户直清。
- 支付方式：关联支付方式。
- 支付插件：关联具体插件。
- 单日限额：超过后通道暂停使用，通常次日生效。
- 单笔最小、单笔最大：限制订单金额。
- 状态：开启或关闭。

常用操作：

- 新增通道。
- 编辑插件配置。
- 测试通道。
- 查看今日/昨日收款。
- 开启或关闭通道。

常见提示：

- “请先配置支付收款商户 ID”：通常表示系统设置中的测试支付收款商户 ID 未配置，或测试商户不存在、不可用、没有可用通道。
- 支付创建失败：检查支付方式是否开启、通道是否开启、用户组是否配置、金额是否超出限额、插件配置是否完整。

### 8. 支付通道轮询

路径：

```text
管理后台 -> 支付接口 -> 支付通道轮询
```

轮询方式：

| 方式 | 说明 |
| --- | --- |
| 顺序轮询 | 按通道顺序依次分配 |
| 随机轮询 | 按权重随机分配 |
| 首个启用 | 始终使用第一个可用通道 |

使用建议：

- 多个同类通道同时可用时使用轮询降低单通道压力。
- 新通道灰度时可设置较低权重。
- 通道失败率高时及时降低权重或关闭。

### 9. 系统设置

路径：

```text
管理后台 -> 系统设置
```

常用配置：

| 配置页 | 用途 |
| --- | --- |
| 网站信息配置 | 网站名称、回调专用网址、用户对接网址、注册开关、测试支付、验证码 |
| 支付相关配置 | 支付开关、支付风控、订单规则 |
| 结算规则配置 | 结算周期、最低结算金额、手续费 |
| 企业付款配置 | 代付或企业付款能力 |
| 快捷登录配置 | 第三方登录 |
| 消息提醒配置 | 邮件、短信、订单、投诉提醒 |
| 实名认证配置 | 商户实名认证能力 |
| 首页模板配置 | 首页显示样式 |
| 邮箱与短信配置 | 邮件、短信服务商参数 |
| 网站 Logo 上传 | Logo 和图标 |
| 计划任务配置 | 定时任务地址和密钥 |

重点注意：

- 回调专用网址必须以 `http://` 或 `https://` 开头，并以 `/` 结尾。
- 用户对接网址会展示给商户作为接口地址。
- 开放注册可设置开启、关闭或仅邀请注册。
- 测试支付收款商户 ID 必须填写站内真实商户 UID。
- 计划任务必须可访问，否则订单通知、结算等自动任务可能异常。

### 10. 计划任务

路径：

```text
管理后台 -> 系统设置 -> 计划任务配置
```

用途：

- 处理订单通知。
- 处理结算相关定时任务。
- 生成或刷新统计缓存。
- 执行系统内部周期任务。

部署要求：

- 宝塔或系统 crontab 中应使用 `https://` 地址。
- 如果任务地址可能跳转，curl 需要加 `-L`。
- 计划任务密钥不得泄露。

排查方法：

- 检查 crontab 是否存在。
- 手动访问任务地址确认返回正常。
- 检查订单 `notify` 状态是否长期为未通知或通知失败。

### 11. 交易投诉管理

路径：

```text
管理后台 -> 其他功能 -> 交易投诉
```

常用功能：

- 查看投诉列表。
- 按订单号、商户号、支付方式、通道 ID、状态搜索。
- 获取最新投诉数据。
- 查看投诉数据统计和排行榜。
- 查看投诉详情。
- 代商户处理投诉。

处理原则：

- 优先处理未处理和即将超时的投诉。
- 结合订单详情确认支付状态、金额、商户和通道。
- 涉及退款时同步核查上游退款能力和商户余额。
- 投诉处理记录应留有清晰备注。

### 12. 黑名单和风控

路径：

```text
管理后台 -> 其他功能 -> 黑名单管理
管理后台 -> 其他功能 -> 风控记录
```

黑名单用途：

- 限制恶意买家账号。
- 限制异常 IP 或风险标识。
- 辅助处理投诉、盗刷、异常订单。

风控记录用途：

- 查看关键词屏蔽。
- 查看订单成功率触发的风控。
- 追踪异常域名、异常内容、异常商户。

建议：

- 不要只凭单笔失败订单拉黑，应结合投诉、支付账号、IP、域名和订单频率判断。
- 高风险商户可先关闭支付或降级通道，再做进一步核查。

## 日常运营检查清单

### 每日检查

- 后台首页今日订单成功率是否明显低于基线。
- 支付方式收入统计是否有异常归零。
- 支付通道收入统计是否集中到单一通道或某通道无成功。
- 订单列表是否有大量未支付、冻结、失败通知。
- 交易投诉是否有未处理记录。
- 结算列表是否有长期正在结算或结算失败。
- 计划任务是否正常执行。

### 每周检查

- 检查商户余额和结算总额。
- 检查高投诉商户和高失败率商户。
- 检查黑名单、风控记录。
- 检查支付通道限额、费率和可用性。
- 检查服务器磁盘、内存、PHP 和 Nginx 状态。
- 检查日志中是否有 fatal error。

### 上线新通道检查

1. 插件文件完整。
2. 后台能刷新出支付插件。
3. 支付方式存在且开启。
4. 支付通道配置完整。
5. 用户组已分配该通道。
6. 单笔最小、最大、单日限额符合预期。
7. 测试商户可发起支付。
8. 支付成功后订单状态变为已支付。
9. 商户异步通知成功。
10. 退款或投诉能力按需验证。

## 常见问题

### 商户无法登录

检查顺序：

1. 确认登录地址是否为 `/user/login.php`。
2. 确认账号是手机号、邮箱还是密钥登录。
3. 检查商户状态是否被封禁。
4. 检查是否缺少手机号、邮箱或登录密码。
5. 如验证码异常，检查短信、邮箱或验证码配置。
6. 必要时由管理员在用户列表中重置密码或检查商户资料。

### 管理员无法登录

检查顺序：

1. 确认登录地址是否为 `/admin/login.php`。
2. 检查管理员账号密码。
3. 检查验证码是否正常。
4. 检查 `@login.lock` 是否因多次失败锁定。
5. 检查 PHP session、cookie、站点 HTTPS 和 Referer 校验。

### 测试支付提示“请先配置支付收款商户 ID”

通常原因：

- 系统设置中未填写测试支付收款商户 ID。
- 填写的 UID 不存在。
- 测试商户被封禁、关闭支付或未完成必要资料。
- 测试商户所在用户组没有可用支付通道。
- 对应支付方式或支付通道已关闭。

处理路径：

```text
管理后台 -> 系统设置 -> 网站信息配置 -> 测试支付收款商户ID
管理后台 -> 商户管理 -> 用户列表
管理后台 -> 支付接口 -> 支付通道
管理后台 -> 商户管理 -> 用户组设置
```

### 订单支付成功但商户没收到通知

检查顺序：

1. 在订单详情查看 `notify` 状态。
2. 检查商户 `notify_url` 是否公网可访问。
3. 检查商户接口是否返回平台要求的成功响应。
4. 检查商户接口是否发生 301/302 跳转。
5. 检查计划任务是否正常执行。
6. 谨慎使用补单，确认商户端幂等后再补发通知。

### 订单大量未支付

排查方向：

- 支付通道是否可用。
- 上游商户号是否异常。
- 金额是否低于单笔最小限额或高于最大限额。
- H5、扫码、App 跳转方式是否与设备匹配。
- 商户域名是否未授权。
- 风控是否拦截。
- 买家是否停留在二维码页面未完成付款。

### 首页统计没有历史日期

当前版本已改为从订单表实时聚合最近 7 天成功订单。若仍不显示：

1. 确认 `admin/ajax.php?act=getcount` 返回 `order` 字段。
2. 检查浏览器控制台是否有 JavaScript 错误。
3. 检查后台登录 cookie 是否有效。
4. 检查订单表是否有最近 6 天的成功订单。

### 支付通道测试失败

检查顺序：

1. 支付方式是否开启。
2. 支付通道是否开启。
3. 支付插件是否存在。
4. 插件配置是否完整。
5. 上游商户号、密钥、证书是否正确。
6. 金额是否符合通道限制。
7. 测试商户是否有权限使用该通道。
8. 服务器是否能访问上游接口。

### 交易投诉列表为空

可能原因：

- 交易投诉功能未开启。
- 当前通道不支持投诉查询。
- 插件投诉配置未完成。
- 上游没有返回投诉数据。
- 投诉数据需要点击“获取最新数据”后刷新。

### 限制 1 元或小额拉单

优先使用支付通道的单笔最小金额：

```text
管理后台 -> 支付接口 -> 支付通道 -> 编辑 -> 单笔最小
```

如果需要全站统一限制或按商户、通道、支付方式分别限制，应通过风控规则或专门开发实现，避免误伤正常低价商品。

## 操作风险分级

### 高风险操作

以下操作必须谨慎执行，并保留操作原因：

- 人工将订单改为已支付。
- 退款。
- 补发异步通知。
- 删除商户。
- 重置商户密钥。
- 修改商户余额或结算状态。
- 批量结算。
- 修改支付通道费率和模式。
- 替换支付插件文件。

### 中风险操作

- 开关支付通道。
- 调整通道轮询权重。
- 修改用户组费率。
- 修改注册开关。
- 修改回调专用网址或用户对接网址。
- 修改计划任务。

### 低风险操作

- 查询订单。
- 查询资金明细。
- 查询结算记录。
- 查看投诉详情。
- 查看统计数据。
- 查看日志。

## 对接验收清单

商户上线前至少完成以下验收：

- API 信息页面可正常查看商户 ID 和密钥。
- 商户系统能生成正确签名。
- 页面跳转支付或统一下单接口可创建订单。
- 支付完成后平台订单变为已支付。
- 商户 `notify_url` 能收到通知。
- 商户能验签平台通知。
- 商户重复收到同一通知不会重复处理。
- 商户订单查询接口可正确返回订单状态。
- 退款能力按业务需要验证。
- 生产金额限制和商品名称符合平台规则。
- 商户域名已授权。
