已签发覆盖 `api`、`pay`、`manage`、`luckrun.helingpay.top` 的有效源站证书，四个虚拟站同时支持 443，保留现有 80。TLS 证书检查通过；外部不带鉴权的直连请求在握手后被原有规则关闭，不能把该结果误认为 TLS 证书故障。证书续期 timer 保持 active，并新增仅适用于这张源站证书的 Nginx 校验及 reload 钩子。

为证书签发和续期，在 API、支付和管理域补入固定 ACME 静态挑战路径；商户域使用原有路径。管理后台其他路径的认证保持原状。配置与操作记录只保存在服务器受控目录 `/srv/epay/backups/20261022-origin-auth`，不含可公开的共享密值。

## 实测结果

API／支付域的健康检查和空参数提交入口共 16 次测试，鉴权头均匹配私有映射，客户端伪造的鉴权头被 ESA 覆盖；未创建订单或调用支付上游。

随后通过四个域共用的真实 FastCGI 片段，对普通请求及伪造请求重复自检：鉴权有效、原始密值已隐藏；但连接没有实际 TLS，两个候选真实 IP 头均未通过与测试源地址的比较。应用解析器按设计返回空观察，没有信任伪造的地址。

两项控制台配置已通过异步提问交由用户完成。启用授权已存在，链路验证通过后可直接设置 `payer_ip_trust_mode=origin_auth`、明确实际真实 IP 头、开启采集并刷新应用配置缓存；无需索要或粘贴共享密值，也无需维护 ESA 网段。

## 继续操作与回退

服务器的 `proof-control.py` 可在受控窗口创建并撤除临时证明检查入口，`database-control.php` 的启用动作会核验私有验收记录后才允许更新配置。验收记录不能用配置截图或用户口头“已完成”替代。采集启用后观察真实新请求的汇总结果，不补写历史 IP，不自动把旧单纳入配额或投诉封禁。

需要回退应用时先关闭采集并刷新配置缓存，再切回上一版本并平滑 reload PHP FPM。ESA 已切 HTTPS 后，必须保留源站 HTTPS 监听、证书、续期和既有鉴权规则；应用回退不能同时撤掉已在使用的 HTTPS 回源通路。
