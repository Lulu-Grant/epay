# PHP 8.4 发布回滚手册

本手册只适用于 PHP 8.4.x 构建之间的应用发布回滚。运行环境保持 PHP 8.4.x；以前的跨大版本运行时切换演练不再是维护流程。具体发布仍受环境授权和运维变更流程约束。

## 触发与准备

持续 fatal error、支付创建或通知失败率明显上升、签名异常、重复入账、权限隔离回退、后台或商户无法登录，均应停止扩大发布并评估回滚。先记录当前提交、部署包、PHP 8.4 补丁版本、配置版本、开始时间及异常指标。

发布前必须保留上一个已验证的 PHP 8.4 部署包及其 Composer 锁文件，并确认当前数据库结构能被该构建读取。如本次含数据库迁移，先完成前后向兼容评估和受控备份；不能仅凭代码回滚假设数据库会自动恢复。备份位置和凭据由运维在受控系统记录，不写入仓库或聊天。

## 执行

1. 暂停后续发布，保留当前日志和必要的脱敏故障证据。
2. 在部署系统选择**上一个已验证的 PHP 8.4 构建**；仅替换该版本的代码与静态资源，不覆盖生产密钥、环境配置或发布后的合法业务数据。
3. 使用该构建对应的 `includes/composer.lock` 和已验证依赖包。若需要重新安装依赖，仍在 PHP 8.4.x 环境执行，先通过平台要求检查。
4. 按运行平台标准流程重启或平滑重载 PHP 8.4 FPM、Web 服务与 OPcache。不要把网站指向旧 PHP 运行时。
5. 若数据库迁移不向后兼容，停止自动回滚并按单独批准的数据库恢复方案处理；不得覆盖发布期间新增的订单、投诉或账务记录。

## 回滚后验证

```bash
php -v
php tools/php84/check-env.php
sh tools/php84/lint-all.sh
sh tools/php84/check-deprecated-patterns.sh
```

随后按[维护验收标准](php84-acceptance-criteria.md)检查首页、后台与商户登录、支付创建、API 错误形状、签名拒绝、回调幂等、计划任务和错误日志。需要数据库验证时，仅在隔离验证库执行 `tools/php84/db-fixture-check.php` 与 `tools/php84/rollback-rehearsal-check.php`；这些脚本不能替代生产发布系统的实际回滚验收。

至少观察 30 分钟，比较回滚前后的支付和通知成功率、P95 延迟、fatal error 及订单状态异常。记录回滚前后 PHP 8.4 构建、执行时间、验证结果和后续修复责任人。已经发生的退款、自动回复、冻结或其他外部动作不能通过代码回滚撤销。
