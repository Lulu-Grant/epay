# 无感商城影子订单验收标准

> 本文档对应 `docs/shop-shadow-order-development-guide.md`。`checkout` 购买确认页仅作为回滚模式，不再是默认目标。

## 1. 结论规则

- P0：任何一项失败均禁止切换 `shadow`。
- P1：正式发布前必须通过。
- P2：发布后持续观测指标。

## 2. P0 原支付不变量

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-DATA-001 | 原商户 | `pre_order.uid` 不变 |
| P0-DATA-002 | 原金额 | `pre_order.money` 不变 |
| P0-DATA-003 | 原商品 | `pre_order.name` 不被随机商品改写 |
| P0-DATA-004 | 原参数 | `pre_order.param` 保持商户原值 |
| P0-DATA-005 | 原回调 | `notify_url` 和 `return_url` 不变 |
| P0-DATA-006 | 单支付单 | 一次商户订单只创建一张 `pre_order` |
| P0-DATA-007 | 唯一附属单 | 同一 `pay_trade_no` 只有一张 `pre_shop_orders` |
| P0-DATA-008 | 原路由 | 使用原商户 gid、费率、通道和子通道 |

## 3. P0 无感支付链路

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-FLOW-001 | 网页支付 | 纳入商户响应中不得出现 `shopping.php?act=checkout` |
| P0-FLOW-002 | 指定支付方式 | 直接进入原支付插件结果 |
| P0-FLOW-003 | 未指定方式 | 直接进入原 `cashier.php` |
| P0-FLOW-004 | MAPI | 保持原 `payurl/qrcode/jsapi/app/urlscheme` 响应类型 |
| P0-FLOW-005 | 无确认节点 | 影子订单 `status_times` 不包含 `confirmed` |
| P0-FLOW-006 | 通道回写 | 原订单分配通道后，`pre_shop_orders.pay_type=pre_order.type` |
| P0-FLOW-007 | 商城失败隔离 | 商城表不可写时，原支付仍能返回原插件结果 |

## 4. P0 影子订单创建

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-SHD-001 | 默认覆盖 | 商城开启且未排除的普通订单创建附属记录 |
| P0-SHD-002 | 排除商户 | 排除 UID 不创建附属记录 |
| P0-SHD-003 | 非普通订单 | `tid!=0` 不创建附属记录 |
| P0-SHD-004 | 随机商品 | 仅从启用、未删除且有库存的商品中固化快照 |
| P0-SHD-005 | 动态金额 | `goods_price=money=pre_order.money`，`quantity=1` |
| P0-SHD-006 | 幂等重试 | 商户重试后原支付单和商城单数量仍为 `1/1` |
| P0-SHD-007 | 随机快照稳定 | 重试、回调和补偿不重新随机商品 |
| P0-SHD-008 | 无商品降级 | 商品目录为空时不阻断原支付 |

## 5. P0 支付、发货与商户通知

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-PAY-001 | 原商户入账 | 支付金额只给 `pre_order.uid` 入账一次 |
| P0-PAY-002 | 自动发货 | 支付成功后商城单为已支付、已发货 |
| P0-PAY-003 | 时间记录 | `status_times` 包含 `paid` 和 `shipped` |
| P0-PAY-004 | 回写幂等 | 重复通知不重复入账、扣库存或降级履约状态 |
| P0-PAY-005 | 原商户通知 | 商城同步后仍执行原 `notify_url` |
| P0-PAY-006 | 通知状态 | `pre_order.notify` 只代表原商户通知结果 |
| P0-PAY-007 | 回调隔离 | 商城回写异常不得阻断原商户通知 |

## 6. P0 CLI 异步补偿

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-REC-001 | CLI 限制 | 补偿脚本仅允许 CLI 运行 |
| P0-REC-002 | 进程锁 | 同一站点同时只有一个补偿进程 |
| P0-REC-003 | 扫描起点 | 不处理 `shop_shadow_started_at` 之前的历史订单 |
| P0-REC-004 | 未支付漏单 | 补建后保持待支付，不自动发起支付 |
| P0-REC-005 | 已支付漏单 | 补建后直接同步为已支付、已发货 |
| P0-REC-006 | 排除规则 | 补偿不为排除商户创建新商城单 |
| P0-REC-007 | 单笔隔离 | 单笔错误不终止后续订单，输出结构化错误 |
| P0-REC-008 | 补偿时效 | 正常调度下 2 分钟内补齐 |

## 7. P1 配置、后台与回滚

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P1-ADM-001 | 流程模式 | 后台可选 `shadow` 与 `checkout` |
| P1-ADM-002 | 排除输入 | 只接受正整数 UID，保存后去重并逗号化 |
| P1-ADM-003 | 无统一收款 | 配置中不存在商城收款 UID |
| P1-ADM-004 | 来源识别 | 订单列表和详情显示“无感影子订单” |
| P1-ADM-005 | 安全 | 管理配置仍校验登录、Referer 和 CSRF |
| P1-ADM-006 | 公共查询 | 仍需 token 或规定凭证，不返回 token 和完整隐私数据 |
| P1-ADM-007 | 回滚模式 | 切换 `checkout` 后可恢复旧购买确认页 |
| P1-ADM-008 | 完全关闭 | `shop_status=0` 时新订单不创建商城记录 |

## 9. 自动化必测场景

1. UID 1000 纳入无感模式，创建 31.00 元指定支付方式订单。
2. 确认响应不包含商城确认页，但已写入商城记录和支付方式。
3. 重复提交同一订单，确认数量仍为 `1/1`。
4. UID 1001 纳入排除清单，确认不写商城表。
5. MAPI 确认保持原支付响应契约。
6. 支付成功调用两次，确认原商户只入账一次。
7. 临时使商城订单表不可写，确认原支付仍返回正常结果。
8. 运行 CLI 补偿，确认未支付漏单被补建。
9. 创建已支付漏单，确认 CLI 补建后为已支付、已发货。
10. Playwright 检查移动端订单查询、桌面商城和后台订单。
11. 切换 `checkout` 并确认旧购买确认页可用。

执行命令：

```bash
SHOP_TEST_REQUIRE_BROWSER=1 bash scripts/shop-feature-local-acceptance.sh
```

## 10. 上线允许条件

- 所有 P0 和 P1 自动化项通过。
- 线上配置默认保持 `checkout`，完成备份和小额验证后才切换 `shadow`。
- 已安装每分钟执行一次的 CLI 补偿任务。
- 已验证 `shop_flow_mode=checkout` 和 `shop_status=0` 两级回滚。
- 真实小额支付只能使用专用测试商户执行。
