## 2. 已实现结果

### 2.1 三项线上问题

1. 投诉获取：保留并重新验证 PHP 8.4 基线中的投诉同步与商户只读查询修复；同步回归和商户只读回归均通过。
2. 通道轮询权重：移除 99 的错误上限，支持历史 100 及 PHP 64 位整数范围内的十进制权重；保存保持字符串精度，处理历史零权重、重复通道、总和溢出、并发覆盖和无变化保存。
3. PC/移动端适配：修复登录、商户首页、导航、筛选栏、表格、轮询弹窗、帮助、商城、收银与结果页的响应式布局；暗色主题不再全局覆盖 Bootstrap 栅格。

### 2.2 业务完整性与权限

- 邮箱采用统一契约：仅 ASCII、总长不超过 254 字节、local-part 不超过 64 字节；只去除首尾空白，不静默截断或整体转小写。
- 写入前读取实际数据库列容量，旧 32 字段会明确拒绝长邮箱；写入后按原字节验证。管理员开户、商户注册、绑定、修改、验证码和找回流程使用同一验证规则。
- 付费注册新增完成账本，商户创建、密码写入、收款入账、资金记录和邀请码更新在同一事务中完成；回调重试不会重复开户或重复入账。
- 管理端进入商户中心采用固定 HTTPS 域名、POST 交接、60 秒一次性票据、浏览器双向绑定、15 分钟独立会话、摘要存储、原子消费、审计和撤销。
- 管理登录 Cookie 始终保持 `SameSite=Lax`；只有一次性流程 Cookie 使用 `SameSite=None; Secure`，避免扩大其他管理接口的跨站暴露面。
- 提现入口会提前显示“结算受限”，直接访问页面仍由服务端校验；没有扩大任何支付或结算权限。

## 4. 数据库与配置契约

数据库版本从 2038 升到 2039。迁移文件 `install/update3.sql` 只扩容邮箱列、增加付费注册完成表和管理员代登录表，并插入默认关闭的配置项。

发布前必须在生产同版本的隔离副本运行 MariaDB 10.11 门禁，确认 DDL 时长、索引、字符集和已有数据分布。邮箱列扩容后不得在应用回滚时缩回 32，也不得用整库恢复覆盖发布后的正常交易。

P5 代登录配置目标值如下，配置完成后仍保持 `admin_sso_enabled=0`：

```text
admin_sso_admin_origin=https://manage.helingpay.top
admin_sso_admin_path=/lpao/sso.php
admin_sso_merchant_origin=https://luckrun.helingpay.top
admin_sso_merchant_path=/user/sso.php
admin_sso_enabled=0
```

启用前须确认管理端真实映射路径、反向代理 HTTPS 识别、两域 Cookie 行为、退出撤销和 60 秒超时。不得通过 URL 传商户密钥或票据。

## 8. 回滚

1. 如代登录已启用，先把 `admin_sso_enabled` 设为 0，并撤销 pending 票据与活动会话。
2. 先回退乐跑覆盖层到 `3062de2`，再回退主仓库到 `af97d2e`。
3. 保留已扩容邮箱列和新增账本/审计表；不要缩列、删表或回滚发布后交易数据。
4. 刷新缓存后复测登录、订单回调、投诉和轮询读取。
5. 若故障涉及数据写入，按交易号和审计关联 ID 做定点核对，不执行整库覆盖。
