# 支付系统故障排查手册

生成日期：2026-07-04

适用对象：平台管理员、运维、开发。

目标：遇到支付、订单、通知、结算、投诉等异常时，按固定路径快速定位。

## 1. 总体排查原则

先判断问题属于哪一类：

- 登录问题。
- 支付创建问题。
- 支付跳转问题。
- 订单状态问题。
- 异步通知问题。
- 退款问题。
- 结算问题。
- 投诉问题。
- 统计展示问题。
- 服务器或计划任务问题。

排查顺序：

1. 确认问题影响范围：单商户、单通道、单支付方式、全站。
2. 确认时间范围：刚发生、持续发生、固定时间发生。
3. 查订单状态。
4. 查商户状态。
5. 查支付通道状态。
6. 查插件配置。
7. 查计划任务。
8. 查 PHP/Nginx/MySQL 日志。

## 2. 用户中心无法登录

现象：

- 商户登录失败。
- 登录后跳回登录页。
- 提示账号或密码错误。
- 提示验证码错误。

排查：

1. 确认访问地址是 `/user/login.php`。
2. 确认商户账号存在。
3. 确认商户未封禁。
4. 确认手机号、邮箱、密码是否完整。
5. 检查验证码、短信、邮箱配置。
6. 检查浏览器是否禁用 Cookie。
7. 检查 PHP session 是否正常。

处理：

- 管理员重置商户密码。
- 修改或补全商户联系方式。
- 临时关闭异常验证码后再恢复。
- 检查服务器 session 目录权限。

## 3. 管理后台无法登录

现象：

- 管理员无法登录。
- 登录提示多次失败锁定。
- 登录后仍跳回登录页。

排查：

1. 确认访问地址是 `/admin/login.php`。
2. 确认管理员账号密码。
3. 检查验证码。
4. 检查 `@login.lock` 是否存在。
5. 检查 Cookie 是否写入。
6. 检查 HTTPS、域名、Referer 校验。
7. 检查 PHP session。

处理：

- 删除异常登录锁文件前先确认不是攻击。
- 修改管理员密码。
- 检查后台登录日志。
- 检查 Nginx 是否正确传递 HTTPS 环境变量。

## 4. 支付创建失败

现象：

- 商户接口返回错误。
- 支付页面打不开。
- 提示支付方式不存在。
- 提示通道不存在。
- 提示金额限制。

排查：

1. 商户状态是否正常。
2. 商户支付权限是否开启。
3. 商户是否完成实名认证或资料补全。
4. 支付方式是否开启。
5. 支付通道是否开启。
6. 用户组是否配置对应通道。
7. 金额是否低于单笔最小或高于单笔最大。
8. 域名是否授权。
9. 签名是否正确。
10. 时间戳是否过期。

后台路径：

```text
管理后台 -> 商户管理 -> 用户列表
管理后台 -> 商户管理 -> 用户组设置
管理后台 -> 支付接口 -> 支付方式
管理后台 -> 支付接口 -> 支付通道
管理后台 -> 商户管理 -> 授权域名
```

## 5. 测试支付提示“请先配置支付收款商户 ID”

原因通常是测试支付配置不完整。

排查：

1. `系统设置 -> 网站信息配置 -> 测试支付` 是否开启。
2. 测试支付收款商户 ID 是否填写。
3. 该 UID 是否存在。
4. 该商户是否正常。
5. 该商户支付权限是否开启。
6. 该商户用户组是否有可用通道。
7. 对应支付方式和支付通道是否开启。

处理：

- 填写一个专用测试商户 UID。
- 给测试商户配置测试用户组。
- 测试用户组只分配少量可控通道。

## 6. 支付跳转异常

现象：

- H5 支付没有直接进入支付 App。
- 显示二维码后再询问跳转。
- 跳到第三方页面。
- 手机端或 PC 端支付方式不匹配。

排查：

1. 支付方式支持设备是否正确。
2. 通道插件是否为 H5、扫码、App 或混合模式。
3. 商户发起时 `type` 是否正确。
4. 浏览器 User-Agent 是否被识别为移动端。
5. 插件返回的是二维码链接还是 H5 跳转链接。
6. 上游是否改变支付页面策略。

处理：

- 确认实际需要的是 H5 原生、扫码、还是收银台模式。
- 拆分不同支付方式或不同通道。
- 给移动端和 PC 端设置不同支付方式。

## 7. 订单已支付但平台未变更

排查：

1. 上游是否真实支付成功。
2. 平台是否收到上游回调。
3. 插件回调地址是否正确。
4. 插件验签是否成功。
5. 订单号是否匹配。
6. PHP 是否有 fatal error。
7. MySQL 更新是否失败。

处理：

- 先查上游订单。
- 再查平台订单。
- 如确认上游已支付但平台未入账，不要直接批量人工补，先定位回调失败原因。
- 单笔人工处理前必须记录证据。

## 8. 平台已支付但商户未收到通知

排查：

1. 查看订单 `notify` 状态。
2. 查看商户 `notify_url`。
3. 用服务器 curl 测试商户地址。
4. 检查是否 301/302 跳转。
5. 检查是否 HTTPS 证书错误。
6. 检查商户接口是否超时。
7. 检查商户返回内容是否符合平台成功判断。
8. 检查计划任务是否运行。

处理：

- 修复商户 `notify_url`。
- 修复计划任务。
- 确认商户幂等后补发通知。
- 对长期失败商户联系整改。

## 9. 订单成功率下降

按范围定位：

| 范围 | 排查方向 |
| --- | --- |
| 全站下降 | 上游整体异常、网络异常、计划任务、服务器错误 |
| 单支付方式下降 | 支付方式配置、设备识别、上游产品异常 |
| 单通道下降 | 通道商户号、插件配置、上游限额、风控 |
| 单商户下降 | 商户业务、域名、用户组、签名、风控 |
| 单金额下降 | 单笔限额、小额限制、上游金额策略 |

临时措施：

- 关闭异常通道。
- 降低异常通道轮询权重。
- 切换备用通道。
- 限制异常商户。
- 调整单笔最小或最大金额。

## 10. 退款失败

排查：

1. 订单是否已支付。
2. 订单是否已退款。
3. 退款金额是否超过可退金额。
4. 上游通道是否支持退款。
5. 插件退款配置是否完整。
6. 商户余额是否足够。
7. 上游证书或密钥是否正确。
8. PHP 是否有 fatal error。

处理：

- 不要重复发起不确定状态的退款。
- 先查上游退款结果。
- 再更新平台状态。
- 必要时人工备注处理。

## 11. 结算失败

排查：

1. 商户结算账号是否正确。
2. 真实姓名是否一致。
3. 结算方式是否开启。
4. 结算金额是否满足最低金额。
5. 商户结算权限是否开启。
6. 企业付款配置是否正确。
7. 上游转账接口是否正常。

处理：

- 填写失败原因。
- 通知商户修改资料。
- 重新发起或人工转账。
- 手动完成前必须确认实际到账。

## 12. 投诉数据不更新

排查：

1. 交易投诉功能是否开启。
2. 支付通道是否支持投诉查询。
3. 插件投诉配置是否完整。
4. 点击“获取最新数据”是否报错。
5. 上游是否有投诉数据。
6. PHP 错误日志是否有 fatal error。

处理：

- 修复插件配置。
- 确认上游权限。
- 单通道验证后再启用全量刷新。

## 13. 后台统计不显示历史日期

当前版本后台首页统计应直接从订单表聚合最近 7 天成功订单。

排查：

1. 登录后台后请求：

```text
/admin/ajax.php?act=getcount
```

2. 查看返回 JSON 中是否有 `order` 字段。
3. 确认 `order` 内是否有最近 6 天 key。
4. 检查浏览器控制台 JavaScript 错误。
5. 检查订单表是否有最近 6 天成功订单。

处理：

- 如果接口有数据但页面不显示，排查前端渲染。
- 如果接口没数据但数据库有订单，排查 `admin/ajax.php`。
- 如果数据库无历史成功订单，页面没有历史金额是正常结果。

## 14. 首页或登录页加载外部资源

排查：

1. 查看页面源代码。
2. 搜索 `http://`、`https://`、`cdn`、第三方域名。
3. 检查 `assets/cdn/` 是否存在本地资源。
4. 检查模板文件引用。

处理：

- 将外部 CDN 改为 `/assets/cdn/` 本地路径。
- 保留本地 fallback。
- 修改后清浏览器缓存验证。

## 15. 服务器健康检查

基础命令示例：

```bash
php -v
php -m
df -h
free -m
crontab -l
systemctl status nginx
systemctl status mysqld
```

检查项：

- PHP 版本和扩展。
- Nginx 是否运行。
- MySQL 是否运行。
- 磁盘是否满。
- 内存是否不足。
- 计划任务是否存在。
- PHP error log 是否有 fatal error。

## 16. 紧急处置顺序

如果出现大范围支付异常：

1. 暂停异常通道。
2. 切换备用通道。
3. 记录异常开始时间。
4. 导出异常订单列表。
5. 通知运营和客服。
6. 排查上游、插件、服务器日志。
7. 修复后用测试商户验证。
8. 小流量恢复。
9. 观察成功率。
10. 全量恢复。

禁止：

- 未确认原因前批量人工改已支付。
- 未确认幂等前批量补发通知。
- 未备份前大规模改数据库。
- 未测试前直接替换生产插件。
