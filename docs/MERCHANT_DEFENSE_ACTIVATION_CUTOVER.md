# 商户防御新订单启用边界

2026-10-23，PHP 8.4。修复活跃商户因历史未支付订单和当日未纳管成功记录长期无法开启防御的问题。历史数量改为核对参考，启用后的新订单才进入浏览器验证、可信 IP、每日额度和投诉封禁流程。发布状态以文末记录为准。

## 生效规则

开启时沿用商户行锁、版本检查、CSRF 和管理员权限，在同一事务写入启用时间与审计。网络、通道、唯一索引及投诉字段检查仍生效，历史清理不再是前置条件。每日最多成功 5 单保障适用于已纳管订单；历史成功订单不追补 IP 或额度。

平台初始入口、浏览器挑战、支付插件入口和额度预占均检查数据库中的实际订单创建时间。未纳管订单必须晚于启用时刻；旧单拒绝再次获取付款信息，提示使用新的商户订单号重新下单。同秒创建的订单保守视为旧单，下一秒可重新创建。请求传入或内存中的创建时间不能覆盖数据库判断。

已有安全纳管订单可在再次验证后沿用原通道、账户、金额和 IP 绑定复用结果，不重复申请上游付款。关闭期间再次发放过付款能力的记录继续占位，不能重新冒充安全订单。关闭再开启不清除成功计数、待确认占位或投诉封禁。

启用前已经发出的上游付款信息，以及开启前已获准的在途请求，无法由本地撤销；真实回调、返回和退款通知继续走原验签及财务流程。旧单工具独立保留核对和逐单阻断能力，不自动调用、关单、退款或清理订单。无法承诺历史链接与新订单的合计付款数也不超过 5。
