# 商户防御待确认订单与对账重试

2026-10-25，PHP 8.4。支付宝 H5 付款信息生成后，上游可能尚未创建交易。此前 SDK 的 `ACQ.TRADE_NOT_EXIST` 被统一记为对账错误，任务又每分钟检查全部待确认订单，造成后台异常列表堆积和重复查询。

## 交易状态与记录

只将支付宝 SDK 返回的确切组合 `code=40004`、`sub_code=ACQ.TRADE_NOT_EXIST` 归为 `NOT_CREATED`。这是待确认状态，不记系统故障，不确认支付，不关单，不删除或重新生成付款信息，也不释放名额。其他 SDK 错误继续作为真实故障处理。查询成功时仍校验订单号、金额、交易状态及上游订单号。

任务分别输出 `waiting`（尚未查到交易或等待买家）、`held`（渠道无法关单，持续占位）、`review`（关闭状态缺少未支付关单证明）和 `failed`（查询、关单、适配器或财务处理异常）。未知名额跨日继续保留，每商户每天每 IP 最多 5 笔成功、投诉封禁 48 小时的规则不变。

新异常记录区分查单、关单和财务处理阶段。支付宝错误只保存经过字符和长度校验的协议错误码，不保存 SDK 原始消息、响应、签名、密钥或付款链接。等待记录按订单、动作及原因只记一次。旧异常日志原样保留，界面标为“历史对账异常（旧版未细分原因）”，不能根据本次抽样把全部旧异常改写为交易不存在。

## 查询频率

沿用 `checked_at` 记录实际检查时间，无需迁移或增加配置。每分钟运行的任务只选到期记录，单次仍最多 100 笔（调用上限 200 笔），继续使用原全局任务锁。

| 资格已等待时间 | 两次查询最短间隔 |
| --- | --- |
| 小于 15 分钟 | 60 秒 |
| 15 分钟至 1 小时 | 300 秒 |
| 1 小时至 1 天 | 1800 秒 |
| 1 天及以上 | 21600 秒 |

付款通知不受查询间隔影响。本地订单已有可信成功状态及支付时间时，优先补齐防御计数，不访问上游；防御已记账但原订单财务处理未完成时，每分钟优先重试，不受订单年龄影响。没有尝试上游调用的预占资格不发起查单，15 分钟后按原规则安全释放；已有可信本地付款时先记账，不因超时释放。

已支付记录不重复记数，退款不恢复成功额度。已经尝试发出的 H5 链接，即使查询不存在或经过 30 分钟，也不会被认作失效链接。查询单独返回关闭状态可能是退款，继续保留核对；只有可信未支付关单回执和独立关闭查询才能释放已经尝试过的资格。
